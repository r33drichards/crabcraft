# Writing a crabcraft guest module (Rust)

A module is a `wasm32-wasip1` **reactor** cdylib that depends on `crab-sdk`.
The SDK implements the WIRE.md codec (section 1) and emits the three ABI
exports (section 2) via `export_abi!`. Full example — `guest/hello` is the
reference:

```rust
use crab_sdk::{Registry, Type, Value};

const SCHEMA: &str = include_str!("../wit/my-module.json"); // wasm-tools component wit --json

fn setup(r: &mut Registry) {
    // Param types are required: the wire encoding is untagged.
    r.register("my:pkg/iface@0.1.0#double", vec![Type::U32], double);
}

fn double(args: Vec<Value>) -> Result<Value, String> {
    let n: u32 = args.into_iter().next().ok_or("missing arg")?.try_into()?;
    Ok(Value::U32(n.wrapping_mul(2)))
}

crab_sdk::export_abi!(schema: SCHEMA, init: setup);
```

`Cargo.toml` needs `crate-type = ["cdylib"]` and the workspace release profile
(opt-level "z", lto, panic=abort, strip) keeps modules ~90 KB. Build:

```
nix shell nixpkgs#rustup --command cargo build --release --target wasm32-wasip1 -p my-module
```

Notes:

- Handlers get decoded params as `Vec<Value>` (one entry per WIT parameter,
  in declaration order) and return one result `Value` — use `Value::unit()`
  (empty tuple, encodes to zero bytes) for functions with no result type.
- `setup` runs lazily on the first `crab_invoke`; no ctors / `_initialize`
  needed.
- Records are positional: `Value::Record(vec![...])` in field declaration
  order. Options are `Value::some(..)` / `Value::none()`.
- Golden codec vectors live in `wit/vectors.json` (generated by
  `cargo run -p crab-sdk --bin gen-vectors`; see `crab_sdk::vectors` for the
  JSON value conventions the Lua harness must mirror).
